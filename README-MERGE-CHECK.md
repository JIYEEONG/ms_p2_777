### 구현 범위와 문서 차이

- 차량 접근은 약 18초로 재생하는 체험이며 실제 관제·배차·결제가 아닙니다.
- 택시 요금은 프로젝트 요금정책 기반의 체험용 경로 예상 요금입니다.
- 설문 추천은 규칙 기반이며 Databricks 또는 외부 추천 모델 연동은 포함하지 않습니다.
- 위치 이용 동의는 브라우저 GPS 권한과 다릅니다. 로그인·설문 문서는 성수역 테스트 좌표 사용을 명시합니다.
- 설문 문서는 V1.8을 기준으로 작성되어 있습니다. 최신 V1.9 기획과의 일치 여부는 별도 대조가 필요합니다.
- 지도 설정 문서 첫머리의 ‘나들이 지도 기존 방식 유지’ 문구와 이후 네이버 코스 지도 설명은 일치하지 않습니다. 변경 코드에는 나들이용 네이버 지도 연결이 있습니다.
- 지도 문서의 경유·도착 마커 드래그 설명은 후속 ‘경유지 드래그 제한’ 커밋 이전 설명일 수 있습니다. 최종 렌트 코드와 화면을 기준으로 허용 동작을 확인하세요.

## 3. main의 관리자 대시보드 유지

main에는 별도로 관리자 대시보드와 로그인 화면의 관리자 페이지 링크가 추가되어 있습니다. 이것은 navermap-적용에서 삭제한 기능이 아니라 분기 후 main에서 추가한 기능입니다.

| 파일 | 병합 시 유지할 내용 |
| --- | --- |
| front/public/moov.html | Google 로그인·설문·지도·요금 연결 + main의 관리자 페이지 링크 |
| front/server.mjs | /api/maps/·/api/auth/ 전달 처리 + main의 /dashboard 경로 처리 |
| front/public/dashboard/ | 관리자 대시보드 HTML·JS·CSS |
| front/app/dashboard/page.jsx | 대시보드 페이지 연결 |
| front/tests/dashboard-source.test.cjs | 대시보드 테스트 |

`moov.html`과 `server.mjs`는 양쪽에서 수정했습니다. 실제 Git 충돌 여부와 별개로 기능 통합 검토가 필요합니다. 파일 전체를 한쪽 버전으로 덮어쓰지 말고 양쪽 변경을 함께 반영하세요.

## 4. 실행 환경과 데이터 확인

- 각 실행 환경의 backend/.env에 네이버 지도·장소 검색·Google 로그인 설정을 준비합니다. 실제 비밀값을 Git에 올리지 않습니다.
- 환경변수 양식은 backend/.env.naver.example 및 backend/.env.google.example을 참고합니다.
- backend/requirements.txt의 로그인 관련 추가 의존성을 설치합니다.
- backend/main.py의 지도·인증·설문 라우터 등록을 유지합니다.
- front/server.mjs의 지도·인증·나들이 API 프록시를 유지합니다.
- 지도용 maps_server.py는 전체 AI·나들이 백엔드를 대체하지 않습니다. 통합 검증에는 필요한 전체 백엔드를 실행합니다.
- 코스 등록·이미지 업로드·활동 기록은 인증이 필요합니다. 호출 계정 ID와 서버 세션이 일치하는지 확인합니다.
- 인증·설문 SQLite 파일은 로컬 저장소입니다. Git 병합만으로 다른 PC의 세션·최신 설문 데이터가 동기화되지는 않습니다.
- backend/account_snapshots/에는 특정 계정의 취향·코스·설정 JSON이 포함되어 있습니다. 공통 초기 데이터가 아니며 저장소 열람자는 파일 내용을 볼 수 있으므로 팀 병합 포함 여부를 확인합니다.
