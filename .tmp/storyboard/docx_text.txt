운영 대시보드 기능 정책과 화면 정의
문서 한눈에 보기
이 문서는 현재 관리자 화면과 백엔드 구현을 기준으로 정보 구조, 공통 운영 정책, 메뉴별 기능과 예외 처리, API 및 데이터 연동, 인수 조건을 정리한다. 모든 화면 이미지는 실제 로컬 관리자 세션에서 백엔드 연결 상태로 캡처했으며, AI 말동무는 인증 후 정상적으로 열린 버전을 기준으로 설명한다.
1 문서 개요
1.1 작성 목적
MOOV 앱에서 생성되는 차량, 상품, 회원, AI 말동무, 공간 콘텐츠와 환경 설정을 운영자가 한 화면 체계에서 확인하고 변경할 수 있도록 관리자 페이지의 기준을 명문화한다. 기획, 개발, 운영, QA가 같은 용어와 판정 규칙을 사용하게 하고 화면과 백엔드 책임 범위를 분리하는 것이 목적이다.
1.2 문서 범위
1.3 독자와 활용 방식
서비스 기획자는 정책 결정과 미확정 항목을 구분해 운영 기준으로 사용한다.
프론트엔드와 백엔드 개발자는 화면 이벤트, 저장 대상, 오류 코드를 구현 기준으로 사용한다.
운영자는 데이터의 출처와 변경 영향 범위를 확인한 뒤 저장과 내보내기를 수행한다.
QA는 각 절의 인수 조건과 예외 사항을 기능 테스트의 최소 기준으로 사용한다.

2 서비스 개요
2.1 관리자 페이지 역할
관리자 페이지는 고객 앱의 운영 데이터를 읽기 전용으로 요약하는 화면과, 차량 상태 및 서비스 설정을 변경하는 운영 화면을 함께 제공한다. 화면 디자인은 MOOV 운영 센터의 기존 좌측 내비게이션, 상단 연결 배지, 카드와 표 구조를 유지한다.
2.2 정보 구조
2.3 데이터 흐름
운영자가 같은 출처의 관리자 URL에 접속하고 로그인 세션을 확보한다.
프론트의 연동 계층이 관리자 부트스트랩과 공용 앱 API를 호출해 초기 데이터를 구성한다.
운영 변경은 인증된 관리자 API로 전달되고 PostgreSQL 또는 Azure Blob에 저장된다.
MOOV 앱은 공용 API와 관리자 상태 스냅샷을 통해 노출 설정을 반영한다.
백엔드 미가동 시 일부 화면은 로컬 호환 저장을 사용하지만 운영 확정 데이터로 간주하지 않는다.
3 전체 운영 정책
3.1 인증과 권한
3.2 데이터 우선순위
정상 연결 시 서버 저장값을 최우선으로 사용한다.
관리자 설정이 아직 서버에 없으면 404를 기준으로 기본값 또는 로컬 호환값을 사용한다.
502 또는 504처럼 백엔드가 일시 불가할 때만 로컬 호환 경로를 허용한다.
401과 403은 권한 오류이므로 로컬 호환값으로 우회하지 않는다.
화면의 예시 집계값은 실제 원장 데이터와 구분해 라벨로 고지한다.
3.3 저장과 동시 수정
3.4 파일과 가져오기
3.5 상태와 오류 표시
성공, 주의, 위험, 미연동 상태는 색상뿐 아니라 텍스트와 배지를 함께 사용한다.
데이터가 없다는 사실과 조회에 실패했다는 사실을 같은 정상 상태로 표현하지 않는다.
버튼을 수행할 수 없는 경우 비활성화하고 선행 조건을 인접 문구 또는 토스트로 안내한다.
파괴적 작업인 삭제, 격리, 테마 삭제는 영향 대상을 다시 확인하는 확인 단계를 둔다.
내보내기는 현재 필터 범위를 따르되 파일명과 열 순서를 고정해 재사용 가능하게 한다.

현재 화면은 외부 차량 서버의 자동 수집이 완료되지 않은 상태다. JSON 가져오기와 일부 앱 연결 이벤트로 기능을 검증할 수 있으나 운영 전 차량 이벤트 수집 경로와 재전송 정책을 확정해야 한다.
8.6 AI 기능 인수 조건
인증된 관리자가 AI 메뉴에 진입하면 3개 탭이 표시되고 프롬프트가 빈 화면 없이 열린다.
네 페르소나를 전환해도 입력값과 자산 영역이 올바른 대상에 연결된다.
설정 충돌 409가 발생하면 기존 화면값을 유지하고 새로고침 후 재적용 경로를 안내한다.
상태 이벤트가 없는 차량은 정상 배지가 아니라 미연동으로 표시된다.
Python 파일 안의 임의 코드는 실행되지 않고 필수 문자열만 읽힌다.

9.5 저장과 예외
선택 테마의 편집값은 실시간 미리보기에 즉시 반영하되 서버 저장은 차량 환경 저장 버튼으로 확정한다.
기본값 복원은 현재 선택 테마만 대상으로 하고 확인 후 적용한다.
저장하지 않은 변경이 있으면 페이지 이탈 전 경고한다.
콘텐츠 테마와 차량 환경의 저장 단위가 다르므로 각각 성공 메시지를 표시한다.
앱 적용은 다음 앱 상태 동기화 시점에 이루어지며 이미 운행 중인 차량에 즉시 강제 적용하지 않는다.
10 공통 예외 처리
10.1 사용자 피드백 원칙
오류 메시지는 무엇이 실패했는지와 사용자가 할 수 있는 다음 행동을 함께 제공한다.
서버 내부 구조, 자격 정보, 스택 추적은 화면에 노출하지 않는다.
재시도로 해결되지 않는 권한과 설정 오류는 반복 요청하지 않고 운영 담당자 확인으로 전환한다.
비동기 저장 중에는 중복 클릭을 막고 진행 상태를 표시한다.

11.1 운영 반영 우선순위
11.2 현재 제한 사항
대시보드 일부 집계와 회원 상단 요약은 화면 설계를 위한 예시 값이다.
차량 위치와 상태에는 실차 연동 전 예시 및 합성 데이터가 포함된다.
AI 사용량의 외부 차량 자동 수집은 미연동이며 파일 가져오기와 앱 연결 데이터가 보조 경로다.
로컬 호환 저장은 단일 브라우저 확인용이며 다중 관리자 운영의 기준 저장소가 아니다.
콘텐츠와 AI 자산 업로드는 Azure Storage 환경 변수가 없으면 503으로 실패한다.
12 기능별 검수 시나리오
12.1 완료 정의
정상 흐름과 대표 예외 흐름이 모두 테스트되고 결과가 기록된다.
화면에 표시되는 수치의 출처가 실데이터, 예시, 미연동 중 하나로 구분된다.
저장 성공 후 새로고침해도 서버 값이 유지되고 앱 반영 범위가 일치한다.
권한 없는 사용자가 관리자 데이터를 읽거나 변경할 수 없다.
주요 화면이 1440 너비와 노트북 높이에서 가려짐 없이 사용할 수 있다.
