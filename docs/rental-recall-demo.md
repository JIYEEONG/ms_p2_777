# 렌트 차량 재호출 체험

산책 중에는 렌트 차량이 대기하고, 이용자가 호출한 뒤에만 선택한 승차 지점으로 이동합니다. 실제 차량·배차 서버와 연결하지 않는 프런트엔드 체험입니다.

## 화면 흐름

1. 나들이에서 `이 코스 따라가기`를 누르거나 홈의 `관심 코스`에서 여러 장소가 있는 코스를 선택합니다.
2. 기존 예약 흐름으로 차량을 요청하고 도착 후 탑승합니다.
3. 이용 중 화면의 `도착·하차 체험`을 누르면 현재 목적지를 방문 완료로 기록합니다. 차량은 인근 도로에 대기합니다.
4. 산책 후 `내 차량 호출`을 누릅니다. 지도, 체험 장소 목록 또는 현재 위치 확인으로 산책을 마친 지점을 선택합니다.
5. `이 위치로 내 차량 호출`을 누르면 같은 차량이 마지막 위치에서 선택한 지점 근처 도로로 접근합니다. 지도에는 내 위치, 차량, 승차 지점이 표시됩니다. 이동은 약 18초 체험이며 바로 옆 차량은 즉시 도착 처리합니다.
6. 도착 전에는 탑승 버튼이 비활성화됩니다. 도착 후 `탑승하고 다음 장소로`를 누르면 방문하지 않은 다음 장소로 연결됩니다.
7. 마지막 장소에서 재탑승하면 코스 완료 화면을 보여줍니다. 새 목적지를 추가하거나 기존 렌트 종료 절차를 진행할 수 있습니다.

## 상태와 연동

- `rentalUX.outing`에 방문한 장소 수, 탑승/산책/호출 상태, 사용자·차량 위치, 호출 시작 시각과 경로를 저장합니다.
- 최초 예약의 `dispatch.vehicle`, `usageStartedAt`, `rentalEndsAt`을 재호출에서 다시 만들지 않습니다. 산책·대기·호출 중에도 이용 시간이 계속 줄어듭니다.
- 차량이 먼저 다음 장소로 이동하는 타이머는 없습니다. 다음 장소로 전환하는 조건은 사용자의 재탑승입니다.
- 호출 취소 시 차량의 현재 위치를 유지하고 다음 호출도 그 위치에서 시작합니다.
- 방문한 장소를 코스 편집으로 덮어쓸 수 없습니다. 코스 완료 후 장소를 추가하면 새 장소부터 진행합니다.
- 기존 `set-route` 메시지로 전달받은 나들이 장소 순서를 그대로 사용합니다. 원본 코스를 잘라내거나 최초 출발지를 호출 위치로 바꾸지 않습니다.
- 호출 시작 시각과 경로를 저장하므로 새로고침 또는 홈 iframe 재생성 후에도 진행률을 복구합니다. 렌트 종료의 개인정보 정리 과정에서 이 상태도 제거됩니다.
- `roadNetwork.buildRecall(origin, pickup)`은 기존 오프라인 도로 그래프의 방향을 따릅니다. 도로에서 400m 넘게 떨어졌거나 연결되지 않은 지점은 다른 승차 위치를 요청합니다.

## 검증

저장소 루트에서 실행:

```sh
node --test front/tests/rental-outing.test.cjs
```

10개 테스트: 명시적 호출 전 대기, 동일 차량·이용 시간 보존, 도착 전 탑승 차단, 중복 호출, 이동 중 취소 후 재호출, 저장 상태 복원, 마지막 장소 완료, 경로 오류, 이용 만료·정리 중 동작 차단, 일방통행과 교차로 경로, 기존 예약·코스 편집·정리 통합 흐름을 확인합니다.

화면 확인은 `front`에서 `node server.mjs` 실행 후 `/moov-home/index.html` 또는 통합 앱 `/`에서 위 순서로 진행합니다. 이번 작업 환경에서는 브라우저의 localhost 접근이 차단되어 시각적 검증은 수행하지 못했습니다. 자동화 테스트의 DOM 대역은 레이아웃 검증을 대신하지 않습니다.

현재 저장소의 오프라인 지도에 연결한 변경입니다. 별도로 진행 중인 네이버 지도 전환 브랜치에는 지도 생성·마커·경로 표시 부분을 해당 지도 어댑터에 맞게 연결해야 합니다.
