# 로그인 취향 설문 (V1.8)

`MOOV_개인화_코스추천_기획보고서_V1.8.docx`의 최종 Q1~Q5 구성에 맞춘 선택형 설문이다.

- 로그인 후 해당 계정의 설문이 완료되지 않았으면 표시한다. 건너뛴 기록이 있으면 저장된 선택을 복원한다.
- 마지막 문항에서 저장을 완료한 경우에만 다음 로그인부터 생략한다. `내 정보 → 취향 설문`에서 다시 수정할 수 있다.
- 미완료 상태로 나들이·렌트를 열면 설문을 다시 표시한다. 저장 또는 건너뛰기 후에는 열려던 화면으로 돌아간다. 로그인 설문에서 건너뛰면 홈으로 이동한다.
- 이전 버튼은 선택을 유지한다. 응답이 없는 문항에는 안내를 표시하고, 기피 지역 목록에서 앞서 선택한 선호 지역을 제외한다.
- 모든 문항은 선택 사항이다. 건너뛰기는 그때까지 선택한 내용을 저장한다. 수정 취소는 기존 응답을 유지한다.
- 한국어·영어를 지원한다. 언어를 바꿔도 선택 내용은 유지한다.

로그인 직후 위치 이용 안내를 먼저 표시한다. 안내 확인 체크 후 `동의하고 시작하기`를 눌러야 설문 또는 앱으로 진입한다. 동의 기록이 없는 기존 계정도 다음 로그인에서 한 번 안내받는다. 저장 실패 시 시작하지 않고 재시도한다.

현재 위치 기능은 성수역 3번 출구의 테스트 좌표를 사용한다. 이 단계는 앱의 위치 이용 안내에 대한 동의이며, 브라우저의 실제 GPS 권한을 받은 것으로 취급하지 않는다. 실제 기기 위치로 전환할 때는 브라우저 위치 권한을 별도로 요청해야 한다.

| 문항 | 내용 | 반영 방식 |
| --- | --- | --- |
| Q1 | 음식점·카페·전시·쇼핑·관광·체험 | 선택 활동과 코스 활동 태그 비교 |
| Q2 | Q1에서 선택한 활동의 세부 항목 | 활동 안에서 세부 취향 비교 |
| Q3 | 선호 지역 | 우선순위 상승, 다른 지역도 허용 |
| Q4 | 기피 지역 | 해당 지역을 포함한 추천 후보 제외 |
| Q5 | 음식 제한·특정 음식·기타 | 알려진 이름·태그와 일치하는 후보 제외 |

Q5 음식 제한 선택지는 구현용 기본 항목이며 `front/public/survey-schema.json`에서 관리한다. 특정 음식·기타는 쉼표로 구분한 직접 입력을 지원한다. 선호 지역과 기피 지역은 중복 저장하지 않는다. 선택하지 않은 활동은 싫어하는 활동으로 처리하지 않는다.

## 저장과 실행

같은 계정의 코스·설문·설정을 다른 환경으로 옮기는 중간 저장은 [계정 데이터 백업 안내](account-snapshot.md)를 참고한다.

기존 지도·로그인 서버와 전체 백엔드 모두 설문 라우터를 포함한다. 새 환경 변수나 외부 서비스 연결은 필요 없다. 코드 변경 전부터 실행 중인 백엔드는 재시작한다.

```powershell
.venv/Scripts/python.exe -m uvicorn maps_server:app --app-dir backend --host 127.0.0.1 --port 8000 --no-access-log
```

- `GET /api/outing/survey`: 현재 로그인 계정의 응답 조회. 미응답이면 `survey: null`.
- `PUT /api/outing/survey`: `version`, `status`, `answers` 저장. 계정 ID는 서버의 Google 세션에서 가져온다.
- `PUT /api/outing/survey/location-consent`: `agreed: true`, `version: "1"`로 위치 이용 동의 저장. `location_consent` 테이블에 계정별 안내 버전·동의 시각만 저장하며 실제 위치나 브라우저 권한은 저장하지 않는다. 조회 응답의 `locationConsent`로 최초 안내 여부를 판단한다.
- 원본 응답은 `user_survey`, 추천용 프로필은 `user_preference` 테이블에 같은 트랜잭션으로 저장한다.
- 로컬 저장소는 `backend/.user-surveys.sqlite3`이며 Git에서 제외한다. 브라우저 저장소에는 원본 설문을 저장하지 않는다.
- 저장 실패 시 입력을 유지하고 재시도한다. 조회 실패 시 완료 여부를 임의로 판단하지 않고 재시도 화면을 표시한다.
- Databricks/외부 추천 모델 연결은 포함하지 않는다. 여러 서버로 배포할 때는 공용 영속 저장소로 옮겨야 한다.

## 추천 적용 범위

`나들이 → 내 취향으로 코스 추천받기`와 `취향순`에 적용한다. 일반 검색·인기순·관심 코스는 직접 탐색하거나 저장한 코스를 유지한다.

후보 제외 → Q1 활동 일치율 → Q2 세부 항목 일치율 → Q3 선호 지역 → 실제 조회된 인기 수·생성일·ID 순으로 정렬한다. 모든 응답이 비어 있으면 인기·최신 기준으로 추천한다. 기존 당일 분위기·동행·시간대·예산 필터는 별도 조건이다. 선택한 활동 일치 개수를 표시하며 임의의 AI 확률이나 이용자 간 유사도를 표시하지 않는다.

세부 태그 형식은 `tags.subcategories = {"카페": ["커피"]}`이다. 데모 코스는 확인 가능한 설명에 따라 별도로 분류했다. 태그가 없는 장소는 일치한다고 추정하지 않는다. 지역은 명시적 태그와 알려진 지역명·주소를 이용한다. 음식 제한은 알려진 이름·태그에 한해 적용하므로 매장의 실제 식재료나 알레르기 안전을 보장하지 않는다.

## 검증

```powershell
.venv/Scripts/python.exe -m unittest backend.test_survey_api backend.test_google_auth_api
node --test front/tests/survey-profile.test.cjs front/tests/outing-data.test.cjs
node tools/check_naver_maps.cjs http://localhost:3000 --login-survey
node tools/check_google_auth.cjs http://localhost:3000
```

브라우저 검사는 별도 프로필에서 인증·설문 응답을 모의 처리한다. 실제 API의 인증·계정 분리·저장·검증은 임시 SQLite를 사용하는 백엔드 테스트에서 확인한다. 실제 Google 계정으로 자동 로그인하거나 운영 응답을 수정하지 않는다.
